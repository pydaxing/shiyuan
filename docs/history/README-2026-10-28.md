# 食愿 · 家庭小厨房

把「今天吃什么」变成一家人共同完成的一餐。

## 源码与版本

当前源码版本为 **1.0.0**，版本规则与上传流程见 [版本与发布](../版本与发布.md)。后文带日期的交付记录用于保留历史，不代表当前线上版本或数据状态。

前端源码在 `src/`，云函数源码在 `server/`，依赖版本由根目录和 `cloudfunctions/kitchen/` 的 `package-lock.json` 锁定。云函数入口 `cloudfunctions/kitchen/index.js` 由 `npm run build:cloud` 生成，不手动修改或提交。

首次从 GitHub 下载后：

```sh
npm ci
cp .env.example .env.production
# 在 .env.production 中填写正式 AppID 和云环境 ID
npm run build:release
```

完成本地构建后，用微信开发者工具打开 `dist/release`，按下方真实云数据验收要求检查。GitHub 保存源码；推送代码、本地构建、部署云函数、上传开发版本、提审和正式发布是不同操作。

`.env.production`、开发者工具私有配置、数据库和媒体备份、验收截图、日志、依赖目录及构建产物不纳入 Git。已有本地文件仍保留在原目录；GitHub 仓库不承担云数据库备份。

## 当前餐食流程（2026-10-27）

菜单选菜 → 厨房已预订 → 可选本餐备菜 → 当天开饭。备菜按菜确认材料，直接编辑本餐用量并自动保存；采购仅接收主动加购的菜品食材包，材料和用量以本餐调整为准、在采购页只读，可按餐或按菜选择本次要买的内容。备齐和加购均可再次点击取消；标记备齐、开饭、取消或删除会清除相关待买包，不改库存，不代表发生真实购买。移除最后一道菜会留下没有菜品的已取消餐单。

安排餐食的今天 / 明天 / 后天下方显示实际月日；厨房仅展示这三天的全部状态餐单，过往与窗口外记录只隐藏不删除，主动待买包不随展示窗口清空。冰箱按冷藏、冷冻、常温、全部排列，有库存时使用双列图片卡片；采购空态按钮与菜单、厨房统一为圆角矩形。

冰箱开关只控制冰箱：开启时底部为「食材」，采购在前、冰箱在后；关闭时底部为「采购」，仍可备菜与采购。每次点击底部食材入口默认打开采购；家庭设置默认打开名称与封面。下单目前仅提示「接入中，敬请期待」，未实现支付、订单、物流或收货。所有表单的字段错误显示在对应控件下方并定位首个错误。页面跨日时，冰箱到期提示与开火日记的今天标记跟随主页面日期更新，不改变库存或用户正在浏览的日记日期。

数据约定见 `UX-CONTRACT.md`；源规则见 `src/domain/meal-preparation.js` 与 `src/domain/meal-shopping.js`。`order.shoppingDrafts` 为可撤销的待买草稿，不是交易订单。

## 现在运行

页面验收统一使用微信开发者工具和真实云数据，不再打开浏览器演示或独立样例项目。当前正式预览目录是本项目的 `dist/release`，项目名称为「食愿」。

```sh
"/Applications/wechatwebdevtools.app/Contents/MacOS/cli" open --project "$PWD/dist/release"
```

手机预览使用 `npm run preview:weixin`，脚本会先核对正式 AppID、云环境、云函数和云端数据模式；不能用本地样例包生成真实验收二维码。

`dist/build/mp-weixin` 是中间编译输出，不另建日常预览项目。既有静态检查、单元测试和编译结果不能代替真实数据验收；真实服务报错时排查服务，禁止回退到演示数据。视觉验收默认只读，不为凑齐状态改动用户的真实记录。

### 多会话修改与统一预览

源码以本项目的 `src/`、`server/` 为准；多个会话使用同一目录时，改动已写入同一份源码，不应再用旧验收目录整包覆盖。微信开发者工具中名称带「验收」的项目是历史时点的独立预览，可能使用本地样例数据，不是另一套正式源码，不再用于页面验收。

日常确认所有改动时只打开本项目 `dist/release` 的「食愿」。统一更新前先备份现有预览、确认没有并行构建，运行全量测试，再以当前源码重新生成前端与云函数。本地重新构建不代表云函数已部署或小程序已发布；保留现有 AppID、云环境、开发者工具配置，不把本地验收数据合进正式包。

## 目录

- `src/domain/kitchen.js`：与界面解耦的食材、订单和库存规则。
- `src/data/seed.js`：原创内置食谱与初始库存，不是抓取的社区内容。
- `src/domain/sharing.js`、`src/services/sharing.js`：分享契约校验、便携图片与内容导出。
- `src/store.js`、`src/services/cloud.js`：本地/云端模式选择、异步保存、同步与失败重试。
- `server/`、`cloudfunctions/kitchen/`：共享领域逻辑、微信云函数与构建产物。
- `deployment/`：15 个集合、索引清单、默认拒绝的数据库/存储权限。
- `src/components/`：菜谱详情与编辑、冰箱、购物单、广场、家庭。
- `src/static/`：本地原创食材插画，详情步骤为示意而非实拍。
- `scripts/build-art.mjs`：可重复生成插画。
- `scripts/build-ui-art.mjs`：生成导航图标与食材默认插画。

依赖锁定与 uni-app 官方 Vue3 模板对应版本；升级时整组更新 DCloud 包并重复双端构建。不要直接强制升级 Vite 跨主版本来消除审计提醒。

**上线前事项**：官方模板和微信服务端 SDK 间接依赖仍有安全告警，详见进度文档；还需真实云权限验收、双账号真机测试、隐私/注销与运营处理流程、备案审核。不要把开发服务器暴露到公网，也不要把本次代码交付描述为已经上线。
