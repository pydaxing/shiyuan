# iPhone 输入生命周期修复 · 2026-09-14

## 本轮问题与根因

用户在 iPhone 17 的新截图中复现了上一版的问题：键盘已经消失但“完成”仍显示、弹层停在半空、弹层下方露出未遮罩的主页；家庭名称输入框被保存区挤住。上一轮模拟器通过不能作为真机已修复的结论。

这次处理共享输入基础设施，不逐个页面增加偏移量：

- 原先把整个遮罩容器的 bottom 跟着键盘一起移动，连背景遮罩也缩短了。现在遮罩始终覆盖全屏，只用容器内部底部留白给键盘让位。
- 原先紧凑弹层保持键盘弹出前的顶部位置，留给输入区的高度不足。现在输入时向上扩展到安全区，收键盘后恢复正常高度。
- 原先 hold-keyboard 阻止原生点空白收键盘，又用脚本判断触摸目标来主动隐藏。原生输入触摸事件被重定向或延后时可能误判。现在微信端交给原生点击空白收键盘，不再用弹层触摸结束事件二次隐藏；网页端保留独立处理。
- 原先仅靠键盘高度归零恢复布局，遗漏或延迟的回调会留下过期高度。现在明确关闭时同步释放焦点与布局状态，失焦后无新焦点也会恢复；无焦点的迟到正高度不会重新顶起页面。
- 手指按下不再取消正在进行的输入框定位，真正滑动超过阈值才取消。滚动位置仍在 Vue 与微信原生渲染完成后测量，不使用旧坐标预测、不先滚到一个中间位置。

## 覆盖范围

所有业务输入仍统一使用 FormField，包括菜名、耗时、营养说明、食材名称/数量/自定义用量、步骤标题/介绍、套餐名称、点餐备注、评论/回复、菜单/广场搜索、库存名称/数量、家庭名称/封面标题、新家庭名称、删除家庭确认、昵称与加入家庭相关输入。

保留 iOS 多行输入的 fixed 坐标声明、同层 input、同步事件分发和隐藏表单卸载。未改变管理员权限、家庭名称确认规则、数据模型或云端接口；未提交测试评论、菜品、订单或家庭修改。

## 已完成验证

- `npm run build:release`：688 项测试通过；微信构建及输入、图片、点击等编译产物检查通过。
- `VITE_DATA_MODE=local npm run build:web`：网页构建通过。
- 微信开发者工具实际原生渲染布局：16 个字段检查通过。模拟 350px 键盘高度，检查字段在滚动区内、未被底栏覆盖、遮罩完整覆盖 932px 窗口；失焦且没有高度归零事件时恢复弹层，随后迟到的正高度事件不重新抬升。
- 这 16 个字段包括多行营养/步骤/评论/备注、数量/自定义单位、套餐名，以及家庭名、封面标题、新建家庭、删除确认、昵称。
- 网页端 402×874 尺寸：真实点击后连续输入、换行、换框、评论回复自动聚焦、点击标题空白失焦；没有用派发 focus 事件替代网页点击。
- 网页端冰箱名称/数量输入后打开嵌套日期面板，回到数量框仍保留草稿并可聚焦；背景滚动前后位置不变，未见浏览器错误日志。测试后恢复原来的冰箱开关，未入库或提交采购。

## 证据与限制

- 构建日志：`artifacts/deployment/input-lifecycle-20260914/build-release.log`、`build-web.log`。
- 可重复布局检查：`node scripts/verify-keyboard-layout.mjs`；需已登录的开发者工具、已有家庭/菜单/广场数据，不执行保存或删除。
- 布局检查结果：`artifacts/deployment/input-lifecycle-20260914/native-layout-regression.json`。方法明确标记为模拟键盘事件，不是物理手机打字。
- 本轮桌面处于锁屏状态，无法完成开发者工具的实际坐标点击键盘测试。网页测试也不能模拟 iPhone 的原生键盘动画。
- 当前修复还需要用新的微信预览在 iPhone 17 上验证。不能宣称所有真机输入问题已经消失。如再复现，应记录真机 focus/blur/keyboardheightchange/scroll 时序，而非继续凭模拟器通过来否定问题。
