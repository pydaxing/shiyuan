## 第一步：今天先体验（不需要小程序账号）

在本项目目录执行 `npm install`，再执行 `npm run dev`，浏览器打开终端地址。

当前用户体验地址为 http://127.0.0.1:4174 ，独立 4186 用于本轮测试。以后可执行 `npm run build:web && PORT=4174 npm run preview` 重启。换端口或 localhost/127.0.0.1 会使用不同的浏览器本地存储；原数据不会自动搬到另一个地址。

建议按这一条路线走一遍：

1. 「点餐」打开番茄炒蛋，查看食材和做法示意图。
2. 点菜品卡片的圆形 + 选中，也可以从广场加入套餐后整套选；套餐与菜品可混选，再次点对钩取消。点击底部「点餐」进入确认页；左侧「清空」只清本次待选及备注，不撤销厨房已提交订单。取消所有菜品后浮栏自动隐藏。
3. 确认页选择今天/明天/后天及早餐/午餐/晚餐/宵夜，切换时间不丢已选菜品或备注。不用选人数或份数，填写可选备注并「送到厨房」。同日同餐合成一单，重复菜只做一道，显示谁选了。厨房仅显示今天、明天、后天，后天预订提交后立即出现；昨天及更早的记录保留但不进入厨房列表或待处理气泡。点订单中的菜直接看做法，头像不显示大厨帽子，「查看备菜用量」只显示总食材，再点「开始备菜」。
   已点过同一餐但未修改时，底部可直接「查看厨房订单」；增减菜品或修改备注后变为「更新这餐选菜」，不会覆盖家人的选择。移除全部自己的菜后可撤回，已做好的一餐需换日期或餐次再提交。确认页「继续选菜」返回菜单，保留当前选择。
4. 到「采购」查看全部未完成点餐合并后的采购量。需要半根玉米时显示买 1 根，按整单位采购；点每项右侧圆形按钮录入实际买入量，可选填到期日期，冰箱关闭时也可设置。启用冰箱后另可拍照上传及选择位置。复制清单和小象选购为清单上方的文字入口；已备齐项自动列在下方，无需展开，没有时不展示该区块。
5. 回到点餐页点击「做好了」，检查冰箱数量减少、采购清单更新；订单卡片显示对应圆形状态印章。家庭「开火日记」默认折叠，连续左右滑动圆形日期，右上角月份随滑动更新，只有开火日有圆点。点击状态行展开各餐菜品列表并查看做法。
6. 去「广场」切换菜品/套餐和分类，固定双列瀑布流；工具行的搜索框支持菜名、套餐名及食材，关键词与分类一起生效，无结果可点「查看全部」重置。卡片或详情点击「+ 加入我家菜单」须再次确认，套餐保留搭配。右侧 + 从已有家庭菜单中选内容并确认分享。菜品可选填营养说明；详情支持发布评论、回复自动聚焦及点赞，自己的分享可以在底部确认删除，已加入菜单的副本保留。当前互动仅在本设备保存，卡片家庭统计未接通时显示「—」。
7. 刷新网页，本机数据应保留。家庭成员仅展示，不能点击切换身份；微信登录与邀请仍待接入。

### 本轮新增的自定义入口

- 点击首页左上角家庭名称或整张首页大图，直接编辑名称、照片和可选标题；「家庭 → 名称与封面」和首页封面相机也保留同一编辑入口，「找点灵感」仍单独进入广场。
- 点击首页菜单右侧「＋菜品」添加菜品、上传封面、填写标准用量，不填写几人份。创建、菜单和广场分类统一为荤菜/素菜/汤羹/主食/其他，小食饮料可选其他。逐个添加步骤，每步标题、介绍、图片都可不填；每步最多 9 张图片，支持批量选择、逐张移除和预览，步骤支持排序与删除。完全空白步骤不保存。
- 点击并列的「＋套餐」选择 2～20 道不同菜品、填写名称，可选封面。套餐不分荤素，选套餐时隐藏分类；全部视图选择具体分类只显示菜品。菜品和套餐右上角 × 可移除，须二次确认；删菜会从套餐移除，不足两道的套餐也移除，订单快照保留。
- 在详情点「分享 → 确认发布」分享到当前设备广场；广场分类工具行右侧 + 仅能选择已有菜品/套餐，不在这里创建。确认前不会发布，再次分享同一项更新原帖子。分享包含家庭名称作为作者，不包含成员列表、订单或库存。当前不是云端公共发布。
- 「家庭」依次为名称与封面、开火日记、家庭成员、习惯开关、使用说明与数据管理；邀请在成员右侧。「我是大厨」只在家庭成员区域显示厨师帽。新家庭冰箱、采购与大厨默认关闭，可在家庭页手动开启；已保存开关保留。关闭不删数据，独立采购记录不会自动变成冰箱批次，但重新开启冰箱后仍抵扣原餐次的采购缺口，不会要求重复购买。
- 点「冰箱」中的全部/冷藏/冷冻/常温卡片筛选，卡片右上角 + 添加食材并预选对应位置，全部入口默认冷藏。新增食材可选择照片；点已有食材图片可替换或移除自定义图，恢复默认插画。
- 网页图片保存于当前浏览器；不会上传到任何服务。相册/相机入口取决于设备支持。空间不足时保持原数据并提示失败，不要把本机数据当云备份。

## 第二步：你需要准备的东西

- 一个微信小程序账号：进入 [微信公众平台](https://mp.weixin.qq.com/) 选择注册小程序，按实际主体填写。
- 不确定个人/企业主体可选类目时，先查后台要求；不要为了功能虚构主体或服务类目。
- 在开发管理中找到小程序 AppID。它是项目标识，不是 AppSecret。
- 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。本机已于 2026-09-08 确认安装，可直接打开并扫码登录。
- 不要发送微信密码、AppSecret、云密钥；由你在官方工具中扫码登录和授权。

## 第三步：将本机代码放进微信开发者工具

1. 修改 `src/manifest.json` 中 `mp-weixin.appid` 为你的 AppID。不要误填最外层的 uni-app `appid`。
2. 执行 `npm run build:weixin`。
3. 在微信开发者工具导入已有项目，目录选择 `dist/build/mp-weixin`，不是项目根目录，也不是 `src`。
4. 如果导入向导要求后端服务，本阶段选不使用云服务；此包仅本地存储。接入云开发时按后续云函数项目配置调整。
5. 编译后查看五个入口、图片和本地操作；再用工具预览二维码进行真机验证（按账号权限提示操作）。
6. 不要手改 `dist` 作为长期修复，它会在下次构建被覆盖。应修改 `src` 再构建。

即使微信包编译成功，仍需你的账号与真机验证原生组件、缓存、胶囊区域和权限行为。当前已通过开发者工具生成测试号预览二维码，但没有代替你注册、扫码或正式发布，也未上传体验版。

本机重新生成手机预览二维码的命令（需开发者工具已登录并开启服务端口）：

```sh
"/Applications/wechatwebdevtools.app/Contents/MacOS/cli" preview \
  --project "$PWD/dist/build/mp-weixin" \
  --qr-format image \
  --qr-output "$PWD/artifacts/deployment/wechat-preview-0.6.0.png"
```

## 第四步：下一轮接入微信云开发

这一步需要写新的云端代码，**当前仓库尚未接入**，不是填一个 ID 就自动支持多人。

1. 在微信开发者工具/云开发控制台按提示开通环境，核对套餐与收费，并设置费用告警。
2. 记录环境 ID，不发送密钥。一般先用一个开发/体验环境，正式上线再规划隔离。
3. 下一轮实现 `bootstrap`、`family`、`recipe`、`order`、`inventory` 云函数与数据库规则。
4. 云端从微信上下文取得身份，验证成员关系；前端传入的 familyId、role、userId 不能作为授权依据。
5. 将本地存储服务替换为云服务适配层；示例数据只在新建演示家庭时显式导入，不上传用户缓存而不告知。
6. 部署云函数、集合索引与安全规则，然后用两个微信号验证真实加入、点餐和库存同步。

你届时只需告诉我「账号准备好了，AppID 是……，云环境 ID 是……」，无需分享密钥；我继续实现云端并逐步指导部署。

## 第五步：给家人体验，不急着正式发布

通过开发者工具上传版本，在小程序后台设置体验版并添加体验成员，家人按平台流程授权后使用。可用范围、人数和身份限制以当时后台规则为准。

按后台提示完成主体信息、服务类目、备案/认证（如要求）、用户隐私保护指引和必要的能力申请；准备审核可用账号/路径、真实截图和说明。提交代码审核，通过后再发布。
