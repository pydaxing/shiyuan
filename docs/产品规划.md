# 食愿：家庭点餐小程序详细规划

规则更新：2026-09-08，点餐采用固定标准用量，同日同餐按菜去重，不再选择人数和份数；套餐逐菜展开、成员头像、营养选填、评论回复/点赞、统一五类菜品与开火日历已实现；家庭成员仅展示，不支持切换身份。当前实现与验证以「进度与验收」0.6 为准。跨设备家庭、公共广场与全站统计仍需云端接入。

## 1. 产品定位

不是一个家庭版外卖平台，而是一个「家庭吃饭协作工具」：大家表达想吃什么，做饭的人确认这一餐，系统算好缺什么，采购的人按单买，买完进冰箱，做完扣库存。

核心闭环：加入家庭 → 建立家庭菜单 → 按日期/餐次点餐 → 厨房确认 → 合并食材需求 → 对照冰箱 → 采购补货 → 做饭完成 → 扣减库存。

默认面向微信小程序，首版聚焦一个家庭、少量成员、家常菜。不做收付款、配送、商家入驻。产品名暂用当前项目名「食愿」，注册名称仍需后台核名。

## 2. 五个一级入口

### A. 点餐 / 今天吃什么

- 顶部显示当前家庭、日期、餐次（早餐/午餐/晚餐），默认当天晚餐。
- 家庭菜单、广场、创建菜品共用荤菜、素菜、汤羹、主食、其他五类；加入家庭后类目保持，支持名称和食材搜索。套餐不强制分类，选套餐时隐藏荤素类目；全部视图选具体类目仅筛单菜。
- 菜卡展示成品图、预计耗时、菜品分类；不显示售价、人数和份数。
- 进入菜品看做法，再选中「想吃」；支持单菜、套餐和混选，默认标准用量。
- 提交前展示已选项目和备注，可取消选中；特殊需求不自动改写配方。
- 一个成员可选多个菜。同日同餐合成一张厨房单，同一道菜只做一道，保留选择人数和成员。
- 订单状态：待确认 → 备菜中 → 已完成；完成前可取消。完成后是历史记录，不重新参与购物需求。
- 厨房可确认或取消；订单内点菜直接看做法，备菜用量仅显示食材。后续增加截止点餐、掌勺人指派。
- 不实现「用户一点击就自动接单」：点餐是愿望，厨师确认才是承诺。

验收：两位真实成员在不同设备点餐后，厨师能看到合并结果；本机阶段只用显式演示成员模拟，不能宣称多人已实现。

### B. 菜谱详情与自建菜谱

- 标题、封面、分类、标准用量、耗时、难度（后续）、作者与来源。
- 配料分主料/辅料/调味料；每项有标准食材、数量、单位。盐等「适量」后续作为非定量提醒，不自动按 0 计算。
- 做法按步骤卡片展示：步骤号、图片、说明；P1 增加步骤计时器与保持屏幕常亮。
- 第一阶段使用明确标注的原创做法示意图；P1 支持每一步的实拍图上传、压缩、删除与内容安全检查。
- 自建菜谱填写基本信息、可增删的食材行、逐步做法；默认仅家庭内可见。
- 后续支持编辑、归档、最近做过、收藏、忌口/过敏原标签、手动选择替代食材。
- 菜谱更新不能改变已提交订单：订单保存当时的菜谱快照和基础份量。
- 外部链接导入和 AI 识图写菜谱均为扩展项，需标明来源、人工校对和版权边界。

验收：不同成员重复选择同一道菜不翻倍用量；步骤图可正常展示；食材名称、数量、单位必填，步骤标题/介绍/图片均选填。

### C. 菜单广场

- 展示名统一为「菜品」和「套餐」：菜品是一道菜，套餐是多个菜品的组合；做法称为菜谱，家庭收藏总表称为家庭菜单。
- 浏览菜单合集 → 查看包含哪些菜 → 一键加入家庭菜单 → 在自己家独立修改。
- 导入为快照副本，保留来源作者、源 ID 和版本；原作者后续修改不强制覆盖家庭版本。
- 重复导入跳过相同来源项，并反馈新增了几道，不复制出多份。
- P1 家庭内可用阶段仅提供审核过的内置精选，不必先做公开社区。
- P2 才开放用户发布、草稿、审核、举报、屏蔽、撤回、违规处置和版权申诉。
- 家庭订单、成员、库存与私有菜谱默认永不公开。公开分享必须单独确认。
- 不采用抓取其他平台图文再发布的方式填充广场。

验收：加入后可编辑和点餐，再次加入不重复；发布前确认，广场 + 仅选择已有内容。卡片底部加入，右侧展示加入家庭数，无云端数据时显示「—」；详情以可选营养说明替代双统计。支持评论、回复和点赞，发布者可确认删除分享，不影响已导入的家庭副本。服务限制统一放在「关于与数据」。

### D. 电子冰箱

- 不只是冰箱：支持冷藏、冷冻、常温三个存放位置。
- 每条记录包含食材名称、数量、单位、存放位置、到期日期（可空）；同食材可有多个批次。
- 食材用统一字典：番茄/西红柿视为同一食材；未知名称仍可手动新增。
- 到期提醒分「已过期」「今天到期」「三天内到期」。这只是日期提示，不是食品安全保证。
- 已过期批次不计入可用库存；当天到期批次仍参与计算，但提醒先检查是否变质。
- 完成烹饪时才扣库存，优先扣最早到期批次；购物清单生成、点餐提交都不扣库存。
- 数量不足时不悄悄扣成负数，提示补录或调整；重复点击完成不得重复扣减。
- P1 增加手动消耗、损耗、盘点纠偏、成员操作日志；P2 再做包装扫码/OCR 辅助录入。
- P1 增加「优先消耗快过期食材」「当前库存能做哪些菜」。

验收：两个批次总量正确、过期不抵扣、kg/g 可换算、个/g 不瞎猜、完成一次只扣一次。

### E. 采购清单

- 根据全部未完成且未取消订单，分配一次可用库存并合并缺口，不设置日期/早中晚过滤。
- 展示库存可用量与建议购买量；缺口按完整计数单位向上取整，需要半根玉米也购买 1 根。
- 按蔬菜、肉蛋、水产、粮油、其他分组是 P1；第一阶段先保证数量正确。
- 已买不是一个装饰勾选：明确确认实际买入数量及保质期，生成库存批次，再重新计算缺口。
- 可复制清单到微信/备忘录；没有订单时显示引导，不生成空白采购成功提示。
- P1 增加临时采购项（纸巾等）、按多人合并周期规划、采购人、采购进度同步。
- 不同日期/餐次共享库存分配，不能把一份库存同时分给两餐；买多的留在冰箱，做饭仅扣实际配方需求。

验收：两道菜都用鸡蛋时合并数量；库存够的食材不出现；买入后缺口缩小；完成的餐次不再产生清单。

## 3. 家庭与成员权限

- P1 微信身份登录；头像和昵称由用户主动填写，不假定能静默获得微信资料。
- 创建家庭并设置名称；一人先支持一个当前家庭，模型保留多家庭能力。
- 邀请链接/小程序码，令牌随机、短期有效、可撤销，禁止使用顺序 ID 作为入家凭证。
- 加入前显示家庭名，由用户确认；支持管理员审批，避免链接转发导致陌生人进入。
- 管理员：改家庭名、管理成员、邀请、设置厨房权限。
- 普通成员：查看家庭菜单、自己点餐、取消自己未锁定的订单、查看冰箱和采购单。
- 厨房/采购能力单独授权；首个管理员默认具备，不能仅凭前端切换角色获得权限。
- 敏感偏好/过敏信息由用户自愿填写，可删除；不会作为医学诊断或自动保证安全。
- 退出家庭立即失去家庭数据访问；删除账号/家庭需确认和后台清理策略。
- 初期不做私聊、定位追踪、手机号收集和社交关系读取，减少权限与审核负担。

## 4. 小象超市：分级实现，不把跳转当下单

1. **确定可控**：生成并复制采购清单，由用户到超市或购物 App 自行选购。
2. **待核实跳转**：如果取得合法有效的目标 AppID/短链或官方入口，可在用户点击后打开小象；没有入口配置不显示可用跳转按钮。
3. **待商务/接口授权**：匹配区域门店、商品 SKU、规格、价格与实时库存；需官方开放能力、合作条件和沙盒验收。
4. **下单和支付**：用户检查地址、替代品、实付金额后主动确认；不能静默购买。接口授权未确认前不进入排期承诺。

微信 `navigateToMiniProgram` 只证明可以按约束打开其他小程序，不证明对方接受食材清单，更不等于已加入购物车。当前没有核实到本项目可用的小象购物车/订单授权接口，所以首版只有清单复制与操作说明，不用猜测的 AppID、不爬取账号、不模拟支付。

## 5. 版本路线与每一步验收

### 阶段 0：本次交付，本机可操作原型

- 完成五个入口和核心数据计算，支持本地保存。
- 同一套 uni-app 代码输出浏览器预览与微信小程序包。
- 验收点：能点餐、看做法、提交、厨房接单、算缺料、采购入库、做完扣库存。
- 本阶段不能让家人跨手机协作；示例广场不是公开社区。

### 阶段 1：一家人真正可用的体验版

- 你注册账号、提供非密钥的 AppID 与云环境 ID；开发者权限在平台授权，不把密码发到聊天里。
- 接微信身份、家庭与邀请、云数据库、云存储、家庭级权限、订单幂等与库存事务。
- 在两部真机完成加入家庭、分别点餐、厨师接单和采购同步；拒绝非家庭成员访问。
- 图片上传持久化并压缩，保留私有与公开存储权限区别。
- 加体验成员，先给家人用；体验范围受微信平台规则约束，不等同正式发布。
- 这是优先上线版本，不以公开广场和小象授权作为前置依赖。

### 阶段 2：日常体验打磨

- 订单编辑与锁单、掌勺排班、重复点餐协调、历史复用与一周餐单。
- 食材单位字典、快过期推荐、库存盘点、采购分类、真实照片和步骤计时。
- 订阅消息只在用户同意和模板合规范围内发送；不能当成任意推送通道。
- 备份恢复、异常监控、数据导出与删除入口，适老字号和弱网重试。

### 阶段 3：公开社区与采购平台合作

- 发布与审核、举报申诉、版权治理、来源版本、推荐筛选。
- 根据主体、服务类目、备案、审核和平台能力确定公开发布方案。
- 有官方授权再对接小象商品匹配和购物车；没有授权就保留优质采购清单，不伪装一键下单。

## 6. 容易忽略但要提前规定的规则

- 取消订单立即移出未完成食材需求；已完成订单禁止重复完成。
- 家庭共用库存不是成员私有库存；多人同时完成订单要在云端事务中校验。
- 库存 1 kg = 1000 g，1 L = 1000 ml；1 个番茄不能自动换成 200 g。
- 未填写到期日期明确显示「未填写」，不推断保质期。
- 示例菜谱用量仅供家庭烹饪参考，用户仍需根据实际食材和熟度调整。
- 手动录入错误、断网、照片失败、拒绝授权必须可恢复，不显示空数据成功。
- 日期按家庭本地日历计算；上线中国家庭默认 Asia/Shanghai，避免 UTC 跨日偏移。
- 分享卡片不包含家庭成员或冰箱库存；公共食谱不默认暴露家庭信息。

## 7. 不做的首版功能

不做微信支付、红包打赏、商家、配送、复杂营养医疗建议、自动采购、无人审核的公开内容、AI 自动猜库存。这些会放大合规和运营成本，却不改善第一天的家庭点餐闭环。

## 8. 上线成本与最省事路径

uni-app + 微信云开发：一个前端工程，云函数/数据库/存储托管，无需自购服务器或维护 HTTPS API 服务；平台备案、隐私说明、服务类目和审核要求仍然要做。

不承诺永久免费或固定费用。小程序主体认证、云环境套餐、存储、带宽、函数和内容安全计费以开通时后台为准。先设置费用提醒，小规模家庭体验后再决定扩容，不提前开通付费采购平台服务。

优先顺序：本机确认体验 → 微信开发者工具本地验证 → 云开发多人体验版 → 合规与正式发布 → 社区和外部采购增强。
