# 内容检测移除

## 当前行为

- 家庭创建/加入/编辑、菜品和套餐保存、采购、评论和回复不再调用微信文本内容检测。
- 分享直接在数据库事务中以 `published` 保存，不再先写 `pending` 再做二次文本和图片检测。写入失败回滚；重复请求使用原回执，不重复发布。
- 相册上传、直接字节上传与授权批量图片导入不再调用图片内容检测。图片格式、体积、归属、压缩版本、加密和访问鉴权保留。
- 删除应用里的检测额度错误映射、额度恢复开关、检测文本分块和检测服务依赖。构建配置不再申请内容检测 OpenAPI 权限。
- 上传文案改为“正在上传”，隐私说明不再声称发布前经过内容检测。

## 不变的边界

字段类型/长度、必填项、有效日期、所属家庭、发布者本人删除权限、官方内容不可由普通用户删除、事务、版本冲突、请求幂等和防滥用限流均保留。这些不是内容检测。数据库或存储故障仍返回失败，不伪装成已保存。

已有图片路径 `approved/` 和历史来源审核/导入回执保留，不改成虚假的“检测通过”。旧版文本处理任务不再执行；旧计划明确提示使用当前批量导入工具，不自动发布历史未公开或已删除的帖子。所有普通新发布均走同一条无内容检测的保存流程。

微信平台的上架审核、主体/类目要求与公开内容管理责任不由应用代码决定。举报和人工处理入口保留，不自动放宽数据库权限。

## 验证

`npm run build:release` 执行全部测试、云函数及微信端构建、原生交互/图片产物测试。编译后云函数在 SDK 的 `openapi` 一旦访问就抛错的条件下，家庭保存和图片压缩/加密上传仍成功；自动检查产物无内容检测调用或额度拦截。

业务测试覆盖菜品/套餐保存、分享、评论回复、文字用量“适量/少许”、幂等、事务回滚、无权删除官方分享、跨家庭图片访问以及授权图片导入续传。线上部署与实际微信调用证据存放于 `artifacts/deployment/no-content-check-20260911/`；只有完成回读核验后才记录部署成功。
