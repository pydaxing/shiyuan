# 分享体验与操作按钮

## 行为

- 我家菜品、套餐详情打开时预备私密分享链接，同一请求合并，最多保留 12 项、15 分钟的内存缓存；不会在启动时批量生成链接。
- 缓存按登录用户、家庭、菜品类型和内容区分。套餐中任一菜品变化、家庭名称变化、切换家庭、退出当前身份、链接临近过期时，不复用旧卡片。订单变化不影响卡片。
- 分享菜单收到有效卡片后才打开，不再在菜单里显示灰色的“正在准备卡片”。封面使用已有图片缓存，图片下载不阻塞分享；未就绪时使用默认卡片封面。
- 首次打开后立刻点分享且网络较慢时，详情中的圆形分享按钮显示短暂的进度环。失败提示重试；不会发送首页替代链接。关闭详情或切换家庭后不补弹旧菜单。
- “分享给微信好友”与“发布到广场”明确区分。后者保留发布确认；微信好友转发仍由原生 `open-type="share"` 完成。

## 视觉

- 菜品、套餐：圆形铅笔编辑、折向右侧箭头分享，保留“编辑／分享”标签和至少 44px 的触摸范围。
- 广场详情及好友分享落地页：两个操作区各占一半；分享为圆形图标配“发给好友”，加入菜单保留明显的文字主按钮。
- 家庭名称与封面、头像昵称编辑入口使用同一组铅笔图标；保留整行可点击及原有说明，不把创建、加入、删除等操作盲目改成无文字图标。
- 新图标由现有 PNG 资源管线生成；不依赖网络图标字体。修正 CSS 作用域插件对动画关键帧的错误加前缀。

## 验证

- `npm run build:release`：625 项测试通过；原生输入、图片、交互、家庭编辑入口检查通过。
- `npm run build:web`：通过。
- 新增 11 项回归测试覆盖请求合并、失效、账户隔离、套餐子菜变化、失败重试、提前关闭、慢网点击、无图片等待和本地预览。
- 微信模拟器实际云端菜品：打开分享菜单时两层分享组件均持有效菜品链接，按钮未禁用。
- 微信模拟器广场详情：两个操作区宽度均为 191px、高度均为 52px，间隔 12px。
- 控制台 `grep -i error` 未命中。截图和构建证据在 `artifacts/deployment/share-polish-20260911/`。
- 新版预览二维码：`artifacts/deployment/wechat-share-polish-20260911.png`。未上传或发布正式小程序，也未修改云函数。

模拟器无法代替两部真机的微信转发验收；还需手机扫码后检查发送给好友及对方打开菜品、套餐。真实家庭菜单和订单没有为测试而增删。
