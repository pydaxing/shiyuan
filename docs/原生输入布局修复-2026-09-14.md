# 原生输入布局修复 · 2026-09-14

> 此轮预览之后，用户在 iPhone 上仍复现了异常。本文件保留当时的判断与验证记录，不代表真机已修复。紧凑弹层固定顶部的策略已撤销，当前修复与验收边界见 `iPhone输入生命周期修复-2026-09-14.md`。

## 范围与原因判断

用户反馈上一轮手机预览仍不能稳定输入：管理中的删除确认失焦，多行营养与步骤介绍跳动，普通单行输入基本正常。此次不把桌面模拟器的成功等同于真机故障已解决。

代码中存在三个可消除的冲突风险：家庭页以 hidden 保留了非当前表单的原生输入节点；切换管理子页后异步重置会收键盘；弹层在实际原生布局更新前依据旧坐标预测滚动。同时提交 Vue 状态，不代表微信原生视图同时完成布局。

## 改动

- 名称与封面只在当前页渲染；管理组件保留草稿状态，但非当前页不挂载输入节点。
- 子页切换同步收起旧键盘，滚动重置本身不再收键盘；新字段聚焦取消尚未执行的重置。删除名称框放在警告前，减少第一次输入需要的位移。管理员权限、完整名称匹配、删除警告均保留。
- 微信端弹层顶部在键盘开合期间保持位置，仅缩减底部空间。移除预测坐标和 reflow 分支，等 Vue 更新和微信原生渲染回调完成后再测量真实输入框、滚动区与滚动偏移。
- 原生渲染使用 `wx.nextTick`。实际构建测试发现 uni API 代理的同名方法不能完成这里的回调等待，已改用微信原生接口并添加回归测试。
- 需要再次滚到相同目标时只发送目标附近 0.1 像素的命令，不先回写一个较远的中间位置。原生滚动事件使测量过期时重新测量；用户主动滑动、关闭弹层或换框仍取消旧定位。
- 多行框去除 iOS 默认内边距，保留固定容器坐标声明，不新增触摸拦截。H5 继续使用 visualViewport 路径。

## 验证

- 完整测试：680 项；包含原生渲染尚未完成、原生滚动通知延后、键盘覆盖/窗口缩小、紧凑家庭面板顶部不移动、切换字段、旧失焦、手动滚动取消和隐藏表单卸载等回归。
- 微信和 H5 构建及编译产物检查通过。
- 微信开发者工具：使用实际坐标点击、键盘字符输入验证删除名称、营养、滚动后的步骤输入，未注入 focus/input 来代替点击。键盘高度 320px 是额外模拟事件，用于检查实际原生布局与输入保持可见；它不是物理手机键盘。
- 删除框连续输入测试字符串后仍聚焦；营养框从底部移动到可见区域后继续输入；滑到步骤区再点多行框，内容和焦点保留；点空白失去输入焦点。
- 未提交菜品、未保存家庭修改、未执行删除；未改变数据库和邀请封面权限；运行时诊断包装已恢复，表单测试已关闭。
