## 换电脑恢复

1. `git fetch origin --tags`，读取本台账与目标版本 JSON。
2. `git show v1.0.1:package.json` 核对源码版本；可用 `git switch --detach v1.0.1` 查看历史源码。不要覆盖未提交修改。
3. 按开发接手指南恢复依赖和私有配置。Git 不含云数据库、云存储、登录态、密钥或完整发布包备份。
4. 用版本记录中的源码提交恢复代码；产物哈希用于验证当时构建的身份。不同运行环境重新构建不保证逐字节相同，不能冒充原上传包。

## 后续必填记录

每次上传前记下版本、完整源码 SHA、构建目标、验证结果、包文件哈希及回退档案位置；上传后记录官方最终状态、完成时间和包大小。待确认和失败不能记为上传成功。提审、通过和正式发布后追加对应证据与时间，保留原上传事实；后端部署另记代码哈希及前端兼容范围。私密原始回执保存在忽略目录，Git 只保存脱敏摘要与哈希。

成功上传后创建并推送 `vX.Y.Z`，标签必须指向上传源码提交。若该标签已存在，核对它指向同一提交；不移动标签。GitHub Release 若后续创建，未上线版标为预发布，正式版只在平台确认上线后标记，不将“上传开发版”等同“正式发布”。
