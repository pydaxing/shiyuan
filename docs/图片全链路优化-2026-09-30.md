## 已定位的代码问题

- 原来虽有 card/detail 缩略图，但每次未命中都由云函数下载密文、解密，再用 base64 JSON 传回设备；批次会等待字节处理完成。
- 单张图片到达会重建整个响应式 URL 映射，让其他图片也重新求值。图片写入队列曾同时承载传输工作，慢图片会拖延其他图片显示。
- 上传选择压缩版本，再压缩到 1400px / 480KiB，不能满足保存真正原图的要求。等待上传的预览却会直接渲染选择的完整手机照片。
- 列表、详情和家庭缓存同步序列化及落盘，位于界面完成更新的路径上。

没有证据表明数据库算力不足或 Vue / uni-app 必须替换；此次保留框架和原生输入、同步点击方案。

## 新链路

| 用途 | 尺寸 / 大小 | 时机 |
| --- | --- | --- |
| 卡片、头像、小格子 | 最长边 480px，最多 80,000 字节 | 可见时加载；上传时也只显示小预览 |
| 详情封面、做法步骤 | 最长边 960px，最多 120,000 字节 | 进入可见区加载，先复用已有卡片图 |
| 原照片 | 保留选择器给出的原文件，单张最大 30MiB | 存储时保留；仅点开图片时请求 |

有些旧照片在早期上传时已经被压缩，不能凭现存文件恢复过去未保存的像素。旧媒体引用不变，原文件内容完整保留；正常记录只补充展示文件，不删除原图。回填中发现 1 张早期明文 JPEG 缺少加密元数据：先保存并验证私有备份，再原位补齐加密封装与元数据，解密后的 652 字节与原文件 SHA-256 完全一致，引用和像素不变；没有把这项失败直接跳过。HEIC 原文件保存为密文，客户端同时提供可兼容的 JPEG 预览，服务端无需依赖云端 HEIC 解码库生成小图。展示图移除 EXIF；原档案保留原文件内容，读取仍受现有媒体权限限制。

新客户端先经云函数检查身份、家庭、分享或公开菜品范围；返回 5 分钟签名清单，设备直接下载私有存储中的二进制图片，不让大量 base64 穿过 JS 桥。首次读取旧媒体会准备展示文件；批量脚本可提前完成这一步。签名请求合并，下载和磁盘写入分开排队。

## 安全与兼容

- **不能只改代码便开启明文文件直传。** `IMAGE_DELIVERY_PRIVATE=1` 仅在生产存储规则验证后设置。默认关闭时不产生明文 delivery 文件，继续旧的鉴权传输。
- 本次未改动存储权限：线上实查为 `PRIVATE`（创建者和管理员可读写）；服务端创建的分发文件不向普通用户开放直读。`deployment/storage-rules.json` 是另一个更严格的部署模板，不能把模板内容当成线上配置。签名 URL 的匿名无签名请求已实测返回 403，不能把 bucket 改成公开读。
- 后端保留旧客户端 base64 响应，防止强制升级导致整个小程序图片失效。旧协议读取大原图只能兼容返回详情图，真正的大原图下载需要新版客户端和私有直传配置。
- 签名过期重新鉴权一次；下载校验响应状态与字节数；家庭切换时清理旧缓存，临时下载文件复制后删除。
- 缓存上限 400 个尺寸文件、48MiB，有磁盘配额失败的逐步淘汰与重试。
- `postId` 只是查询提示，服务端仍核对发布状态及图片是否属于帖子，不能借此越权。
- 旧图回填入口只接受无小程序 OPENID 的后台调用，且要求服务端保存的短期任务、密钥摘要及精确文件清单，每次最多 3 张，只准备 card/detail。
- 回填客户端默认两条工作队列，逐批持久化进度，可安全停止与续跑。已有小图仅并行复制；需要从源图压缩的批次保持串行，避免堆积大图解码内存。更新回执只解析计数，不把数据库的 64 位内部时间戳强制转成 JavaScript 数字。

## 部署次序

1. 授权官方腾讯云 CLI，读取实际存储权限，确认 `PRIVATE`；不能将公开读存储用于家庭原图。
2. `npm run build:release`，用 `node scripts/deploy-cloud-verified.mjs --live --private-images --output artifacts/deployment/image-performance-20260930/cloud` 打包 Linux 图片依赖，核对 Active 状态及部署代码 SHA-256，再保留其他环境变量并启用分发开关。
3. 真机验证签名 URL 所在下载域名；不要通过开发者工具“不校验域名”宣称通过。本机的签名下载已验证成功，但这不替代 iPhone 微信域名检查。缩略图的域名错误可回退至原有鉴权传输，原图会明确提示配置问题。
4. 配置 `TCB_CLI` 指向已授权 CLI，然后运行 `node scripts/prewarm-image-delivery.mjs` 做只读清点。确认清单后用 `--live`，默认输出至 `artifacts/deployment/image-performance-20260930`。重试复用同一目录，已经完成的图片不再处理，失败项记录原因。
5. 在新版微信包上验证卡片、教程和点开原图，验证冷缓存/热缓存、网络失败、换家庭及 iPhone 相册多图。最后再提交小程序更新。

若要回退直传，将 `IMAGE_DELIVERY_PRIVATE` 关闭即可；不应删除原档案或已生成的小图，也不必修改菜品数据。不要直接回退到不支持大原图的老后端。
