# 安排状态与餐食记录

- 新版「已记录」只对应已保存的餐食。旧 completed 值不作为记录存在的证据；读取当前安排时核对关联记录，缺少记录显示「历史已结束」，已删除显示「记录已删除」。不批量改写旧订单，不自动重建删除的日记。
- 已记录、记录已删除、历史已结束均保留原安排并占用餐次；用户可删除原安排后重新安排。删除安排不删除已发布的餐食。仅隐藏自己的家庭日记不改变共享安排状态。
- 关联当天安排成功保存才结束安排。明后天仅可安排，独立实拍不结束安排。旧客户端完成接口仍兼容，但不会被新版误称已有日记。
- 同餐次占用时按钮统一「确认安排」，保持不可重复提交；提示根据真实状态显示，链接定位原安排。服务端错误文字去除旧开饭称呼。
- 关联安排的手动记录和自动归档共用创建安排时的成员快照；历史缺快照时采用有凭据的点餐参与者。不关联安排的实拍以发布时的成员为快照。成员后来加入或离开不改写已经记录的归属。实际发布者仍拥有自己发布的记录和删除权限。
- 自动归档只处理过去日期，保留显式隐私和删除标记，不改变旧订单状态。安排页展示今天、明天、后天。

验证与部署结果以对应发布记录为准；自动化测试不替代真实微信界面验收。
