# 家庭邀请、好友分享与多家庭

## 使用路径

- 家庭页 → 家庭成员最后的「＋邀请」卡片 → 微信好友选择器 → 发送邀请。
- 好友打开邀请 → 查看家庭名称 → 自愿填写昵称、选择头像 → 确认加入。
- 家庭页 → 我的头像与昵称：修改个人资料，同步到自己加入的各个家庭。
- 家庭页 → 切换与管理家庭：新建、切换、退出、移除成员或删除家庭。
- 家庭菜品／套餐详情 → 分享 → 发给微信好友。此操作不会自动发布到广场。
- 广场菜品／套餐详情 → 发给好友。好友无需创建家庭即可查看完整配料、步骤和图片。
- 查看好友分享后，可以创建自己的家庭，再把菜品或套餐加入我家菜单。

## 身份与授权

云函数继续使用微信提供的可信 `OPENID` 识别账号，不信任客户端传入的用户 ID。首次访问不要求填写手机号、密码，也不会自动加入家庭。

头像采用微信 `button open-type="chooseAvatar"`，昵称采用 `input type="nickname"`。它们是用户主动选择的资料，不是实名认证，也不能静默读取微信头像、昵称。头像上传需要用户操作，服务端验证图片归属。首次创建家庭或接受邀请需要明确确认共享资料和家庭记录。

## 多家庭与权限

- 一人最多创建或加入 10 个家庭，每个家庭最多 20 人。
- `users.familyIds` 保存成员关系，`users.familyId` 保存当前家庭；兼容旧单家庭账号，按需迁移，不清空旧数据。
- 菜单、套餐、订单、冰箱、采购、封面、偏好和日记按家庭隔离。
- 切换会清空上一家庭的临时选餐与打开的编辑面板，重新同步新家庭；服务端拒绝带旧家庭 ID 的延迟写入。
- 普通成员可以退出；管理员可以邀请或移除成员、删除家庭。管理员退出时必须选择其他成员接任，转交和退出在同一事务内完成；只有一人的家庭须先邀请接任者或删除家庭。管理员也可以只转交权限而不退出。详见《家庭角色与邀请验收-2026-09-11》。
- 删除家庭必须由管理员输入完整家庭名称确认。
- 删除采用逻辑删除：清除成员关系并关闭访问，业务记录不立即物理抹除，客户端不可恢复。其他家庭、已发布广场内容和他人已导入的副本不受影响。

## 邀请与分享数据

- 邀请使用 48 位随机十六进制 token，24 小时有效；用户不需要复制或输入代码。
- 打开邀请只读取家庭名称和成员数，不自动加入；重复确认不会重复占用名额。
- 移除／退出成员时撤销该家庭旧邀请，避免凭旧卡片再次加入。
- 家庭菜品与套餐分享保存在新建的私有 `shares` 集合，使用随机 token，30 天有效。
- 分享仅包含被选中菜品／套餐的做法与图片，不包含成员、库存、订单等家庭私有记录。
- 家庭被删除或分享者被移除后，其未导入的私有分享链接失效。接收方已导入的副本及图片仍可使用。
- 广场分享按公开菜品 ID 查看；原公开内容删除后，旧分享入口不能继续读取，但已导入副本不受影响。
- 访客的图片访问仅授权分享涉及的图片。缓存按账号、家庭及分享 token 隔离。
- `shares` 从创建时起使用 `{ "read": false, "write": false }` 安全规则，只能通过云函数鉴权访问。
- 旧邀请码接口仅用于兼容旧客户端，新界面不展示邀请码。

## 验证与上线边界

自动化测试覆盖多家庭隔离、切换冲突、创建幂等、邀请过期／撤销、重复加入、所有者删除权限、头像归属、访客配料和步骤读取、菜品／套餐分享、私有图片隔离与导入后保留。

微信开发者工具内验证真实云端邀请预览、实际菜品分享与详情渲染。两部手机的转发、好友首次进入、头像选择器和加入确认仍需要真实微信账号联合验收，不能用单账号模拟器结果替代。

预览二维码不等于公开上线。预览／体验阶段，接收方受微信开发者／体验成员权限限制；让任意新用户直接打开卡片，需要完成微信审核并发布正式版。上传体验版或提交审核应单独执行，不由本次生成预览二维码隐式完成。
