先读 [发布版本台账](发布版本台账.md) 和 `docs/releases/`。截至 2026-10-28 21:33:33（北京时间），最新成功上传开发包为 **1.0.3**，对应 Git 标签 `v1.0.3`；这不等于线上版本。下面较早的 1.0.0 接手基线属于历史记录。后续遵守 AGENTS.md 中 Git 与微信版本对应规则。

## 新电脑启动

### 已验证的环境

- macOS，Apple Silicon。
- Node.js **v24.20.0**、npm **11.19.0**。
- 官方微信开发者工具，登录有小程序开发权限的账号。

这是本项目实际用过的环境组合，不代表 Windows、Linux 或其他 Node.js 版本已经验证。仓库暂未用 `engines` 或 `.nvmrc` 强制版本；接手时优先保持上述组合，避免同时升级工具链与修改功能。

### 下载与安装

公开仓库可直接下载，clone 不需要原私有仓库的访问权限：

```sh
git clone https://github.com/pydaxing/shiyuan.git
cd shiyuan
npm ci
cp .env.example .env.production
```

用 `npm ci` 按锁文件安装，不先运行 `npm update`。根目录与云函数依赖锁都使用 npm 官方下载地址；`npm ci` 会安装依赖，不会部署代码或写入业务数据库。

### 配置微信与云环境

**独立开发者**使用自己的微信小程序 AppID 和 CloudBase 环境，并同步更新 `cloudbaserc.json` 的 `envId` 与函数名。按 [正式云端部署](正式云端部署.md) 在自己的环境创建集合、规则、索引及云函数；其中现有项目标识和历史运维记录不是可以直接照搬的部署目标。前后端必须指向同一环境，保留 `VITE_DATA_MODE=cloud` 和 `dist/release` 的真实微信验收方式。

**接手食愿原项目的协作者**另行取得开发权限和原环境配置，再按下表核对；GitHub 仓库公开不会授予生产云端权限。以下“现有环境”只适用于已经获得授权的协作者。

在本机 `.env.production` 填写配置：

```dotenv
VITE_DATA_MODE=cloud
VITE_CLOUD_ENV=填写自己或已获授权的云环境ID
VITE_CLOUD_FUNCTION=kitchen-v2
WEIXIN_APPID=填写自己或已获授权的小程序AppID
```

| 配置 | 核对来源 |
| --- | --- |
| `VITE_DATA_MODE` | 固定使用 `cloud` 进行正式预览与验收 |
| `VITE_CLOUD_ENV` | [cloudbaserc.json](../cloudbaserc.json) 的 `envId`，同时核对实际微信云环境 |
| `VITE_CLOUD_FUNCTION` | 同一配置文件的 `functions[].name`，当前为 `kitchen-v2` |
| `WEIXIN_APPID` | [正式云端部署](正式云端部署.md) 中已记录的正式 AppID，并与微信开发者工具核对 |

AppID 和云环境 ID 是项目标识，不是登录密钥。它们存在于工程文档和配置中，但仅知道标识并不获得云端访问权限。不要把微信密码、AppSecret、腾讯云 SecretKey 或 GitHub 令牌写入仓库；`.env.production` 已被忽略。

### 构建与微信预览

```sh
npm run build:release
```

该命令运行现有测试，构建云函数和微信前端，检查原生交互，再生成 `dist/release`。它不会自动部署云函数、上传微信开发版本或正式发布。

在微信开发者工具导入 **`dist/release`**，项目为「食愿」。不要导入仓库根目录、`src/` 或独立演示项目。Mac 默认安装位置也可这样打开：

```sh
"/Applications/wechatwebdevtools.app/Contents/MacOS/cli" open --project "$PWD/dist/release"
```

登录后核对 AppID、云环境和云函数，使用现有真实云数据验收。生成手机预览使用 `npm run preview:weixin`；脚本先执行 `verifyPreviewTarget`。开发者工具需已登录并开启服务端口；安装路径不同时，通过 `WECHAT_DEVTOOLS_CLI` 指定官方 CLI。

真实服务不可用时排查配置、登录和权限，不切换到本地样例数据冒充通过。代码静态检查和测试通过，也不能证明线上页面或多人权限已经验证。

## 源码地图

| 路径 | 职责 |
| --- | --- |
| `src/main.js`、`src/App.vue` | 应用初始化与全局入口 |
| `src/pages/index/index.vue` | 主页面与主要功能入口 |
| `src/pages/shared/`、`src/pages/invite/` | 好友分享、家庭邀请落地页 |
| `src/components/`、`src/composables/` | 界面组件、页面行为与可复用交互 |
| `src/store.js` | 应用状态、家庭与业务操作的前端协调 |
| `src/domain/` | 食材单位、餐单、备菜、采购、家庭、分享等领域规则 |
| `src/services/` | 云调用、缓存、图片、原生分享、保存队列和反馈 |
| `server/wechat.mjs`、`server/application.mjs` | 微信云函数入口和服务端业务分发 |
| `server/` 其他模块 | 身份与家庭权限、数据访问、分享、媒体处理、删除与一致性 |
| `src/static/`、`assets/` | 应用内资源和品牌素材 |
| `tests/` | 领域、接口、组件与构建契约的自动化测试 |

| `scripts/` | 构建、预览、上传、验证及历史数据运维工具 |

云函数的源文件在 `server/`。`npm run build:cloud` 生成 `cloudfunctions/kitchen/index.js`，正式包复制到 `dist/release/cloudfunctions/kitchen-v2/`。不要编辑生成文件后反向覆盖源码。

## 修改后的检查

| 命令 | 用途 |
| --- | --- |
| `node --test tests/对应文件.test.js` | 验证本次修改涉及的既有测试 |
| `npm test` | 运行全部自动化测试 |
| `npm run build:cloud` | 从服务端源码生成云函数入口 |
| `npm run build:release` | 生成供微信开发者工具使用的正式云模式工程 |
| `npm run preview:weixin` | 核对构建目标并生成微信预览二维码 |
| `npm run release:check -- --published-version 已核实线上版本` | 核对源码版本一致性和版本递增 |

部分测试需要监听 `127.0.0.1`。若运行环境报 `listen EPERM`，先区分沙箱端口限制与代码失败，不通过删测试或放宽鉴权来消除错误。2026 年 10 月 28 日源码副本共验证 2,121 项现有测试，其中 18 项本地传输测试在允许回环监听后重跑通过；这只是当时的验证记录。

多个 Codex 会话可能同时修改同一源码。先看 `git status` 和最新差异，避免重复覆盖；同一 `dist/` 输出不得并行构建。更新既有正式预览前，按 `AGENTS.md` 备份产物和保留开发者工具配置。

## 版本与发布事实

当前接手基线为源码 **1.0.0**，`src/manifest.json` 的内部 `versionCode` 为 **10000**。继续开发时以实际 `package.json` 为准，并按 [版本与发布](版本与发布.md) 同步所有版本字段。

2026 年 10 月 28 日 12:05:39（北京时间）的本地回执确认 1.0.0 **上传开发版本成功**，当次没有确认提审或正式发布。此前最后明确核验的线上版本为 0.6.1，发布时间为 2026 年 10 月 20 日 10:05:40。再次发布前必须重新核实平台状态，不能把这段历史记录当成实时线上版本。

原电脑的上传证据位于 `artifacts/version-1.0.0-20261028/`；同日云函数部署证据位于 `artifacts/production-release-20261028/backend/`。这些原始回执不在 Git 中，换电脑后不能假装已经读取。需要复核时安全取得原始证据，或在有权限的官方工具中重新查证。

本项目当前的 `release:upload` 使用本机 `wechatide` 包装器，默认路径为 `/usr/local/bin/wechatide`，并要求其支持 `-c Codex` 与脚本预期的 JSON 成功回执。该工具没有打包进仓库。新电脑须先恢复兼容工具并通过 `WECHAT_IDE_CLI` 指定路径，或另行适配并验证官方上传流程；不能直接把该变量指向普通微信 CLI 后假定参数和输出兼容。

云函数部署另需可用的 CloudBase `tcb` CLI、`TCB_CLI` 路径和对应账号授权，按 [正式云端部署](正式云端部署.md) 的 Linux 依赖打包、线上备份与代码回读流程处理。Git 推送、本地构建、云函数部署、微信开发版上传、提交审核和正式发布，是分别核验的操作。

## 头像存储与性能约定（1.0.3）

头像原图保存到私有云存储，`users.avatar` 与家庭成员头像保存稳定 cloud 文件引用；数据库不存图片二进制，也不持久化微信临时路径。新头像生成独立 `avatar` 小图，最长边 192 像素、20,000 字节预算，小图不放大原图。前端使用 avatar 变体、优先队列和持久本地缓存；换头像通过新文件标识失效，仍保留必要的权限刷新。不能将“有缓存”描述为永不访问网络。

本次历史头像审计共 10 份媒体记录，并非 10 位用户；当前账号小图已保存，132×132、2,712 字节。其余 9 份批量维护被 `client_context` 身份检查拒绝，任务已失效，不要移除鉴权来绕过。正常有权限用户读取时会生成并持久保存缺失小图；批量补齐仍待排查。真实微信预览已看到当前成员头像，未测手机弱网耗时。
