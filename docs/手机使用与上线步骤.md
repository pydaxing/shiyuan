# 食愿小灶：手机使用与上线步骤

## 现在能用什么

2026-09-09 保存速度优化后的最新云端预览二维码：`artifacts/deployment/wechat-save-speed-20260909.png`，请退出旧预览并扫描新码更新手机上的前端，无需清空或重建家庭数据。包含之前的图片上传修复与即时交互反馈。

这不是原来 4174 的本地网页。菜品、套餐、家庭设置、成员、订单、库存、采购、分享、评论等保存到微信云开发；照片经检查后加密保存。免费体验环境已开通，本次没有购买或开启自动续费。

目前是**云端预览版**，不是微信搜索可见的公开正式版。292 项自动化测试通过；真实微信身份下的模拟器云端业务验收通过，不代表两台手机的键盘、相册和网络情况已验收。

## 第一次打开

1. 用微信开发者工具当前登录的微信号，扫描电脑上展示的二维码。
2. 已创建家庭的账号直接进入「我们的小家」；若出现欢迎页，填写称呼并创建家庭，或选择「加入家庭」。
3. 菜单为空是正常的：云端不灌入假的家人、菜品、评论、订单，旧本地演示数据也没有自动上传。
4. 若微信提示没有访问权限，先核对扫码账号。未发布版本受开发者/体验成员资格限制，家庭邀请码不能代替微信平台的访问资格。

## 日常怎么用

- **添加菜品**：点餐页「＋菜品」，填名称、分类、食材；可加封面、步骤说明和多张步骤图片。至少创建两道菜后，可以「＋套餐」组合。
- **点餐**：选中想吃的菜/套餐，点底部「点餐」，再选今天、明天、后天及早餐、午餐、晚餐、宵夜，提交后厨。套餐与单品混选会按菜品去重。
- **做饭**：「厨房订单」按餐次查看，点菜名看做法，依次备菜、开饭。厨房只展示今天到后天，完成的历史餐食保留在开火日记。
- **采购**：根据当前待做餐食计算，整件食材向上取整购买；餐食完成、取消或过期后，不再保留其待采购需求。不开冰箱也可以直接做饭。
- **家庭设置**：点首页标题/封面或家庭页「名称与封面」编辑；家庭页可开关冰箱、采购和大厨身份。
- **邀请家人**：家庭页「邀请家人 ＋」复制 12 位邀请码；对方打开同一小程序，选「加入家庭」填写。24 小时有效，重新生成旧码失效。后台还未发布时，须先配置体验成员并使用可供其访问的体验版。
- **刷新家人操作**：应用前台约每 20 秒检查变化，没有变化不替换页面数据；弹出编辑面板时暂缓后台同步，关闭后在下一轮检查。也可在家庭页「管理 → 同步最新数据」手动完整刷新。

## 本次保存速度优化

- 这次优化实际云端保存，不只提前拨动开关：开关与家庭设置不再读取全部菜品、套餐、订单和库存；其他操作也只读取需要的列表。成功后返回带家庭版本的变更，不再每次保存后整库刷新。版本不匹配或重试结果不确定时，仍完整刷新；旧预览协议继续兼容。
- 小图一次请求完成检查、加密和存储，不再先申请上传票据、上传临时文件、让云端下载再处理；较大图片保留原有上传通道。图片审核、独立加密密钥和访问鉴权没有放宽。
- 步骤图片最多同时处理两张，显示已处理数量；部分失败时保留成功上传的图片，并明确提示，不要求全部重传。
- 同一微信模拟器调用真实云端，每项前后各 3 次中位数：冰箱开关 1418→744ms，大厨开关 1380→681ms，家庭设置 1946→1325ms，单张 28KB 项目插图 3966→1730ms。记录见 `artifacts/deployment/performance/before-saves.json`、`after-saves.json`。测量等待真实保存返回，没有将即时视觉反馈当作落库耗时。
- 测量家庭的业务列表为空，设置按原值提交，没有改动其内容；图片测量不含相册选择和压缩。大图、弱网、首次冷启动、大量菜品仍可能更慢，不能将这些数字当作所有手机的承诺。
- 新上传链路另在微信运行时验证单张封面、两张步骤图、私有本机缓存和鉴权解密回读；用合成图替代相册选择，结果在 `artifacts/deployment/saves-speed/live-result.json`。

## 前一版交互优化

- 广场首次进入立即请求，加载期间显示双列占位，只有请求成功且确实为空才显示空提示；搜索等待期也不闪空。30 秒内返回同一筛选直接显示内存缓存，过期则保留内容刷新；发布和删除会使缓存失效，失败提供重试。
- 家庭开关及底部导航先响应手势，再排队保存；连续点击保留最后选择，旧请求响应不会把开关拨回去。失败恢复当前已确认状态并提示错误，等待期间显示「保存中…」，不把未保存状态当作已落库。
- 点餐、广场和分享页的类型筛选，以及创建菜品、套餐入口补齐轻触振动；按钮原有的即时按压效果、完整触摸范围保持不变。
- 微信运行时注入 300ms 保存延迟，开关投影在 1ms 内变化，连续开/关按序执行；250ms 模拟加载期间不会显示空状态，返回命中缓存不重复请求。记录见 `artifacts/deployment/interaction-native-runtime-20260909.json`。这些是受控模拟器结果，不是真机帧率或网络延迟。
- 全量读取改为并行查询，读取前后校验家庭版本，避免混入其他成员正在修改的数据；无变化时只验证成员资格与版本。
- 后台同步去重，未变化的列表保留原引用；进入广场先显示已有内容，再更新结果。
- 上传成功并通过审核后，直接缓存本机图片，不再立即下载同一张照片。云端审核、加密和图片访问权限不变。
- 同一空家庭、模拟器调用真实云端各 5 次：完整读取中位数 702→518ms，无变化同步 693→360ms。记录见 `artifacts/deployment/performance/before.json`、`after.json`；这不是手机滚动帧率、冷启动或多图大菜单的性能结论。

## 图片上传修复

旧预览选图后报 `undefined is not an object (evaluating 's.cloudMode')`，原因是压缩后的网页 canvas 局部变量在微信异步代码二次转译中遮蔽云模块引用。已将网页处理拆为独立函数，并在每次微信构建后执行 ES5 二次转译的产物回归检查。

修复前后均在微信运行环境复现核对；另用合成图片替代相册选择结果，实际执行微信压缩、真实云端审核上传、加密及私有缓存，单张封面、两张步骤图和鉴权下载均通过。证据 `artifacts/deployment/image-upload-fix/live-result.json`。手机相册授权与选图界面仍请使用新预览码验证。

## 现在请在手机上验证

先反复切换点餐/广场，轻点「全部、菜品、套餐」及创建入口，再快速开关冰箱、采购和大厨身份；确认有按压/振动反馈，开关立即变化，保存结束后重新进入仍保留最终选择。系统未开放振动时仍有视觉反馈。

1. 创建一道自己的菜，上传照片，编辑步骤文字；确认键盘、页面滑动和保存正常。
2. 退出小程序，再从微信最近使用的小程序进入；确认刚才的菜还在。
3. 点一餐，进入厨房并开饭；确认采购不再保留这一餐的待买食材。
4. 有第二位体验成员后，测试邀请码加入、两人点同一道菜合并、头像显示及同步；独立家庭不应看到私有菜品和照片。

## 正式公开上线还剩什么

1. 上传已验收代码，在微信后台设置体验版和体验成员，完成双真实账号/两台手机验证。
2. 完善真实运营主体与联系渠道、隐私保护指引、数据删除/注销处理机制、备案及与实际功能相符的服务类目。公开分享和评论不能靠改名字当作不存在。
3. 完成依赖安全评估、备份和告警配置，提交微信审核；审核通过后再点击发布。

小象超市现在支持跳转/复制清单，没有接入官方购物车或自动下单接口。详细技术验收和未完成事项见 `docs/正式云端部署.md`。
