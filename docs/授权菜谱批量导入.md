# 授权菜谱批量导入

2026-09-11 更新：本文描述的是私有来源暂存阶段。用户后续明确确认本批内容并要求直接批量发布，现采用[管理员确认批量导入](菜谱后台批量发布.md)；确认记录不会伪装成平台审核结果，旧暂存档仍保留原状态，实际公开状态以 `posts` 和最终回读回执为准。

## 两种状态必须区分

“数据入库”不等于“广场公开”。管理员整理的来源可以先批量入库，不必逐道创建家庭菜品、分享、删除临时菜品。图片文件转存和平台内容检查仍独立记录；源文复核或图片解码成功不能冒充微信审核通过。

此次管理员导入复用已有、禁止客户端直接读写的 `imports` 集合，使用 `kind: authorized_recipe_staging_v1` 和 `recipe-stage-<来源URL摘要>` 标识。它与原来的家庭收藏记录使用不同 ID 和字段，不更新家庭、菜品、帖子、订单或成员，也不会影响收藏计数。小程序没有读取或发布这些暂存记录的入口。

## 数据结构

- `source`：原始标题、作者、来源链接、介绍、贴士、用料、步骤和原图地址。原始 HTML 仍完整保存在本地归档，云端保存其摘要及绑定该摘要的复核记录。
- `recipeDraft`：按应用类目和食材格式归一化的菜谱。数字用量保持数字，“适量”“少许”保留文字，多图步骤保留每一张图的位置和顺序。
- `assets`：原图摘要、尺寸、字节数、来源地址及上传副本摘要。未上传的 `fileId` 为 `null`，不生成虚假的云文件 ID，也不直接依赖外站热链。
- `sourceReview` / `validation`：复用已绑定来源正文的内容与类目复核，并重新检查文件哈希、完整解码、尺寸、应用 schema 和做法重复。记录不宣称逐张人工视觉审核。
- `moderation` / `status`：明确为平台检查未完成及等待图片/平台检查，不写成公开帖子。
- `contentDigest`：整个文档的稳定摘要。重跑仅补缺失记录；云端有不同内容时停止，不覆盖。

## 执行

```sh
node scripts/admin-recipe-import.mjs
node --test tests/admin-recipe-import.test.js
node scripts/admin-recipe-import.mjs --live --cloudbase-cli /绝对路径/tcb
node scripts/admin-recipe-import.mjs --live --verify-only --cloudbase-cli /绝对路径/tcb
```

第一条逐条检查归档、读取实时广场来源并生成导入包，不写数据库。`--live` 才写入，`--verify-only` 只核验、不补写，并保留原写入回执。目标 AppID 和云环境从 `.env.production` 获取，并核对正式构建 AppID；不新建环境。

使用官方 CloudBase CLI 的 NoSQL `INSERT` 命令，不使用客户端接口或伪造登录身份。一次逻辑导入内部按请求字节数分批，避免把多 MB 文档数组塞进开发工具传输层。每批分发前保存 ID、正文摘要和意图，逐批保存云端回执，最后完整回读每条文档进行字段比较。发生部分失败或未知结果时停止；下次执行先回读，不盲目重传。

不传 `--cloudbase-cli` 时可使用开发工具文档数组插入，仅适合较小批次。开发工具若返回确认任务，记录任务 ID 并停止，不能换工具规避确认。第一次约 2.56 MB 的整包调用返回 MCP 500，随后回查暂存记录为 0；这次传输错误不等于数据库写入慢，也不能算导入成功。

完整回读也优先走官方 CloudBase CLI：开发工具会截断较大的 JSON 返回值，导致无法解析。CloudBase 返回的 Extended JSON 数值会还原为真实数值，再比较原始字段；不因回读解析失败重新插入已成功的数据。

## 产物与验收

产物目录：`artifacts/recipe-full/admin-import/`。

- `inspection.json`：全部归档逐条检查结果，包含不导入的理由。
- `documents.json`：本轮合格且未发布菜谱的完整暂存文档数组。
- `insert-documents.json`：排除实时已发布和已暂存记录后的本次写入内容。
- `database-receipt.json`：实际写入状态、分批请求及最终完整回读结果。只有 `staged_verified` 表示暂存入库完成，`publiclyPublished` 仍为 `false`。
- `insert-result-*.json`：各批腾讯云原始回执。
- `first-mcp-attempt.json` / `first-mcp-reconciliation.json`：首次开发工具传输失败和未写入的证据。

`materializeStagedRecipe` 仅在全部图片的云文件和上传正文摘要已核对后，才把图片引用还原成通过应用校验的菜谱。此步骤本身不发布。后续发布单独记录实际采用的平台检查或管理员确认方式，再生成 `posts` 的卡片、分类、搜索字段和图片访问索引；不能直接把暂存状态改成 `published`，也不能将管理员确认写成微信检查成功。
