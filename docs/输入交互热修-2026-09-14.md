# 输入交互热修 · 2026-09-14

## 后续真机反馈

用户确认此版仍存在删除名称框闪退焦点、营养和步骤多行输入跳动；因此下文的开发者工具通过不能视为问题已解决。后续处理与新预览见 `docs/原生输入布局修复-2026-09-14.md`，不要继续用本文件末尾旧二维码验收。

## 问题与修复

用户反馈上一版在手机上所有输入框无法聚焦。共用 FormField 新增了 catchtouchstart，拦截了原生输入的触摸起始阶段，是本轮优先移除的回归风险。开发者工具未稳定复现手机上的全部输入失效，不能把推断说成已在真机证实的唯一根因。

- 移除 FormField 的 touchstart、mousedown 拦截，不用触摸处理器代替系统聚焦。
- 输入本身与容器带 keyboard-field 标记，原生容器额外使用 mark。弹层据此跳过输入区的收键盘和打断自动定位逻辑。
- 保留独立的 tap 冒泡隔离，避免跨组件重定向后的点击在页面上被当作空白收键盘。验证中曾移除此隔离，发现搜索框首次点击失效，已恢复后重新构建并实际点击验证。
- 点空白仍可收键盘；滚动、点当前输入、切换输入及迟到事件不误收新焦点。
- 不改变输入内容、删除确认保护、家庭权限或数据库，不重新部署云函数，保留此前的邀请家庭封面实现。

## 验证结果

- `npm run build:release`：675 项测试通过，微信原生产物检查通过。
- `VITE_DATA_MODE=local npm run build:web`：通过。
- 微信开发者工具使用实际坐标点击，再发送键盘字符，而非调用 bindfocus/bindinput：家庭名称、删除确认、营养疗效、滚动后的步骤介绍均保留输入；最终包另验证搜索框首次点击输入与套餐名称输入。
- 测试文本仅留在未提交的表单，不提交菜品或套餐，不点击确认删除家庭；家庭名称测试字符已撤回。
- 新增覆盖：聚焦先于触摸、原生内部节点无 dataset、H5 内部节点、跨组件 tap 隔离、输入触摸起止不被 catch 阻断。
- 原有 `verify-input-cover-ui.mjs` 已适配标记，但仍只用于事件处理器模拟。此轮未将其作为点击聚焦通过的证据。

这些是开发者工具验证，不是真实 iPhone 键盘验证。真机需检查首次点击、连续输入、换框、点击空白收键盘和滚动后再次输入；新预览不代表已提交审核或公开发布。
