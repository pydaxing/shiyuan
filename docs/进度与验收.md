## 0.6 点击分发与输入定位时序

- 本轮不改页面布局，集中处理公共点击和键盘定位。原逻辑在聚焦后 280ms 即使还没有键盘高度也会滚动；当键盘事件较晚到达，会再按缩小后的区域定位。现在聚焦只登记字段，收到键盘高度或可视区域变化后再定位；已经展开键盘时换输入框仍会定位，表单校验主动定位也保留。
- 滚动位置改为读取 scroll-view 当前测量值，不依赖可能滞后的 scroll 事件。普通定位只下发目标位置，不先回写旧位置；重复同一目标时只用实测当前位置同步控件。测量期间若平台又滚动，丢弃混合帧坐标并重新测量，避免先向一个方向滚动再反向纠正。
- 保留同层 input、fixed textarea、关闭系统重复上推、非动画坐标更新、手动触摸取消定位，以及嵌套弹层背景锁定。显式关闭 scroll-anchoring，网页内滚动容器关闭浏览器滚动锚定，避免另一套定位机制同时拉动内容。
- 检查当前 uni-app 微信运行时发现：tap 默认通过额外的 setTimeout 分发。微信构建统一给按钮及文字、图片等原生命中节点设置 data-eventsync，使用当前运行时支持的同步分发路径；构建产物会检查实际输出，不修改依赖文件。业务动作仍在平台认定的 tap/click 后执行，不在 touchstart/touchend 上提前执行，也未合成第二次点击。保留原有禁用、确认及防重复提交逻辑。
- 按压反馈直接显示，不再等透明度渐变；松手恢复仍使用轻微过渡。命中区域不缩放、不移动。

## 0.6 微信原生输入层错位修复

- 用户真机截图显示：聚焦步骤标题后上下滚动，文字与输入框背景分离，多行输入难以聚焦、键盘闪退。上一轮网页缩屏和事件模拟未覆盖微信原生控件的独立渲染层，不能据此判定真机问题已解决。
- 对照微信官方 input 文档：iOS 输入框默认在聚焦时切到非同层原生状态，且明确不建议聚焦期间使用 CSS 动画。公共 FormField 单行输入现统一设置 `always-embed=true`，覆盖菜名、步骤标题、套餐名称、食材数量、家庭名称和搜索等入口。
- 对照微信官方 textarea 文档：处于 `position:fixed` 区域必须显式声明 `fixed=true`。现按是否位于 Sheet 中传递 fixed，覆盖步骤介绍、营养描述、评论/回复和点餐备注；保留 `adjust-position=false` 的单一自定义避让，不叠加系统自动上推。
- 撤回上一轮弹层 bottom/height/max-height 和底部 padding 的 CSS 过渡，程序输入定位恢复非动画滚动。手势滚动仍由平台处理，不以定时动画移动原生输入框坐标。
