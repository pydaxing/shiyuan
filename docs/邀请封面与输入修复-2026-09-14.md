# 邀请封面与输入修复 · 2026-09-14

## 输入回归补充

用户随后反馈旧预览包在手机上全部输入框无法进入。下文 671 项测试与原生事件脚本不证明真机点击聚焦正常，旧二维码不应用来验收本次修复。当前热修与验证边界见 `docs/输入交互热修-2026-09-14.md`。

## 本次变更

- 家人邀请页使用被邀请家庭当前设置的封面，未设置时使用该家庭默认头像。读取邀请后再加载展示图，布局保持固定高度，避免图片加载引起位移。
- 持有效邀请的访客只能读取该家庭当前封面的压缩展示图，不因此获得原图、其他家庭图片、菜单或成员资料的权限。仍需明确同意后才能加入家庭。
- 邀请页面退出时清理图片授权上下文；迟到的网络响应不能重新安装已退出页面的授权。
- 原生输入、文本域、滚动容器的触摸事件与按钮一样同步分发，避免触摸回调晚于聚焦事件到达。
- 弹层先测量当前输入位置，再同时提交键盘布局和滚动位置，移除“先缩小面板、等待一段时间、再滚动”的两阶段处理。
- 收键盘仅由在同一个输入焦点下完成的空白轻触触发；滚动、换输入框、迟到的点击事件不会误收新输入框的键盘。表单容器不再使用会重定向原生焦点的 label 包裹自定义输入组件。
- 删除家庭的确认输入保留名称匹配保护与管理员权限，不自动聚焦、不自动提交或执行删除。

## 验证结果

- `npm run build:release`：671 项测试全部通过，微信输入、点击、图片、交互、分享产物检查通过。
- `VITE_DATA_MODE=local npm run build:web`：通过。本地浏览器验证营养疗效、步骤介绍、家庭名称输入保持焦点，未保存测试内容，无浏览器控制台错误。
- `node scripts/verify-input-cover-ui.mjs`：在微信开发者工具执行实际构建产物的原生事件处理器；删除确认可输入匹配名称并启用按钮，未点击确认删除；营养和步骤文本保留，聚焦后的触摸/点击没有调用收键盘；空白轻触只收一次键盘。
- 真实云端 `readInvite` 返回的封面与家庭封面一致，压缩图读取成功。模拟器邀请页图片实际可见，尺寸为 388 × 144，不仅核对了文件 ID。
- 云函数 `kitchen-v2` 已通过官方 CloudBase CLI 更新并回读验证为 Active，代码 SHA256 与本地一致。这里只更新服务端和生成预览包，不代表提交或通过微信版本审核。

键盘高度事件由自动化模拟，不等同于物理 iPhone 键盘。仍需手机扫码检查弹出动画、连续输入、切换字段及收键盘手感；尚未由第二个真实微信号验收邀请封面，跨家庭权限由自动化测试覆盖。
