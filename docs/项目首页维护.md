封面字体使用 macOS 的宋体与系统中文黑体，生成好的 PNG 已入库，浏览者和新电脑无需安装字体即可查看。其他系统重新生成时可能使用后备字体，请检查字形与排版。

家庭名称、封面等资料未更改，没有支付操作。这次数据操作授权只适用于当轮工作，不能扩展为今后制作截图时可以任意更改真实数据。后续换图默认只读，新增、修改或删除家庭内容仍遵循当前用户授权与 `AGENTS.md`。公开前已检查展示图没有家庭邀请 token、邀请码或加入二维码；公开家庭 ID 是展示标识。

`family-diary` 截图中成员头像加载为空，原图与合成图均保留该真实状态，没有补画或替换头像。

菜谱图片、文字和署名保持原界面归属，仅用于展示产品体验；项目代码的授权不能替代这些内容的授权。提交前检查个人资料、邀请码和内部数据。不能通过重画、替换文字或拼造菜品、餐单来补足宣传图。

### 安全区合成与源码分离

`scripts/build-readme-phones.mjs` 只处理文档图片，与 `src/`、`server/` 和小程序构建产物分离。更新 README 或运行图片脚本，不代表修改小程序界面、部署云函数或发布微信版本。

合成保留应用正文、顶部导航与底部标签为一个完整图像区域，等比例缩放后放进标准 iPhone 17 边框的安全矩形，避免灵动岛及屏幕圆角遮挡任何应用内容。原模拟器的刘海与圆角不带入效果图；时间、状态图标和底部系统手势区域分别放入对应的系统安全区。应用区域外的窄留白使用相邻边缘颜色延展，不拉伸、重绘或裁掉应用界面。

默认边框原生尺寸为 388 × 800，应用安全矩形为 `left=24, top=64, width=340, height=672`。脚本会检查该区域完全位于透明屏幕开口内，并逐像素比较合成前后等比例缩放的应用区域，确保边框与遮罩没有修改应用像素。[`phone-composition-report.json`](images/readme/phone-composition-report.json) 记录原图尺寸、应用区域哈希、输出位置及 `frameOrMaskChangedApplicationPixels: 0`；该比较验证合成保真，不能替代真实微信页面的业务验收。

默认导出倍率为 2，含透明留白的合成图为 832 × 1656。倍率只影响输出分辨率，不改变截图比例，也不会增加边框源图本身的细节。透明边缘与轻微阴影用于适配 GitHub 的浅色、深色背景。

### 手机边框与再生成

边框来源为 [WebMobileFirst 的 Apple iPhone 17 页面](https://www.webmobilefirst.com/en/mockups/apple-iphone-17-2025/)，使用页面下载按钮提供的透明 PNG（388 × 800）。2026-10-28 核对的[许可条款第 9 节](https://www.webmobilefirst.com/en/license-agreement/#mockups)允许在个人、商业项目中使用放入自有截图后的合成图，但禁止再分发独立边框文件。因此仓库只提交最终效果图，独立边框保存在被 Git 忽略的 `artifacts/` 中，不打包、不赋予 MIT 等开放许可。

重新生成时，从来源页面下载边框并存到本地忽略目录。先在采集目录生成并检查效果：

```sh
node scripts/build-readme-phones.mjs \
  --frame artifacts/readme-showcase-20261028/device-source/iphone17.png \
  --source-dir artifacts/readme-showcase-v2-20261028 \
  --output-dir artifacts/readme-showcase-v2-20261028
```

命令默认按上表顺序生成全部八张图，也可在后面追加 `family-cover discover` 等基础文件名，只更新已经备好原图的页面。缺少原图时会报错，不应用旧图或模拟内容替代。2026-10-28 已核对脚本默认名为 `fridge`，产物正是 README 使用的 `fridge-phone.png`。

八张原图确认后，按上表名称保存到 `docs/images/readme/`，再省略 `--source-dir` 与 `--output-dir` 执行一次，即从仓库原图重建最终展示图。所用 `sharp` 已包含在项目开发依赖中；新电脑只阅读 README 无需下载边框，重新生成才需要本地素材。若改用其他尺寸或几何的边框，必须先显式提供 `--geometry` 并验证安全区，不能沿用不匹配的坐标。

提交前逐一检查八张效果图：刘海没有残留，灵动岛没有重复，顶部标题、正文与底部导航完整，文字和菜品图片清晰；同时在实际 GitHub 页面检查浅色/深色背景、窄屏横向滑动、八列顺序及大图链接。后续更换边框来源或型号时，重新核对尺寸与许可，不能把旧机型文件改名当成新机型。

## 顶部小标签（Badges）

徽章可以用 Shields.io 的图片地址，也可以使用仓库内的 SVG。当前选用本地 SVG，减少外部图片请求。版本徽章读取 `package.json`，其他徽章标注实际技术栈。更新版本后重新运行上面的脚本并提交产物，同时检查 README 中版本图片的 `alt` 替代文本。

```html
<img src="docs/images/readme/badges/version.svg" alt="源码版本 1.0.0" height="24" />
```

当前没有 LICENSE 文件，因此没有添加 MIT 或其他开源许可证徽章。将来确定授权方式时，应先落实 LICENSE 与第三方资源边界，再添加对应徽章。没有接入 CI 时也不显示自动构建通过或覆盖率徽章；源码版本徽章不代表微信正式版已发布。
