# 预览二维码云服务权限修复

## 问题与根因

用户扫码进入小程序后，`cloud.callFunction` 报 `-601034`（没有权限，请先开通云开发或者云托管）。小程序界面已加载，因此不是二维码过期导致无法识别。

2026-09-30 实际检查发现：

- 正式配置和 `dist/release/project.config.json` 使用 AppID `wx1fe9d6db08a0e91b`。
- 先前二维码命令却指向 `dist/build/mp-weixin`，其中 AppID 仍为测试号 `wx064ea991e5e41495`。
- 包里的云环境 `cloudbase-d8gqg3oqed7609824` 和函数 `kitchen-v2` 是正式目标，测试身份无法因此取得正式云权限。
- 官方 CloudBase CLI 只读检查：云环境 `NORMAL`，函数 `Active`。本次没有更改云权限、购买服务、重建数据库或修改家庭与菜品数据。

## 修复

1. 正式构建同步两个输出目录的 AppID，中间产物保持平铺布局，最终包保留 `miniprogram/` 与 `cloudfunctions/`。
2. 新增 `npm run preview:weixin`，固定从 `dist/release` 生成二维码。生成前检查正式 AppID、目录布局、前后端云环境、函数名称、编译后的云模式与目标字符串；配置不一致时拒绝生成。
3. 保留图片缩略、缓存、原图按需加载和全局关闭震动的修改。本轮不修改 UI 设计。
4. 图片优化版和无震动版之前发送的测试身份二维码不再用于验收，新码位于 `artifacts/deployment/preview-access-fix-20260930/wechat-preview.jpg`。

## 验证范围

`tests/release-preview.test.js` 覆盖正式身份、测试 AppID 拒绝、错误目录拒绝、环境与函数不匹配、旧编译配置、本地演示包拒绝，以及实际构建流程中两个输出目录的 AppID 一致性。测试构建使用隔离临时目录和模拟编译子进程，不访问用户数据库。

云端状态证据位于 `artifacts/deployment/preview-access-fix-20260930/cloud-state.json`；预览目标和官方工具包大小分别保存在同目录的 `preview-target.json` 与 `wechat-preview-info.json`。官方工具生成成功只证明预览上传和身份选择成功，不能替代 iPhone 真机扫码连接验证，也不代表已经提交审核或公开发布。
